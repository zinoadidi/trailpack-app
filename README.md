# Trailpack app

The web frontend for Trailpack, an invite only study app. Drop in your documents, walk out ready.

This is a single page app in vanilla ES modules. There is no build step and no framework. Everything runs from static files, works offline after the first load, and stores its data on the device first.

The backend contract this app talks to is in [`API.md`](./API.md). The build plan is in [`SPEC.md`](./SPEC.md). Current state and gaps are in [`STATUS.md`](./STATUS.md).

## Run it locally

You need Node 20 or newer. There are no dependencies to install for the app or the dev server; the folder is served by a Node script that also provides a mock API.

```sh
npm test            # secret scan, unit tests and mock API contract tests
npm start           # mock API plus static server on http://localhost:8787
```

The server prints an owner login and one unused study code. Open `http://localhost:8787/`, enter the code, and create an account. Everything is in memory and is lost when the server stops.

You can also hand out more codes from the Admin screen after signing in as the owner.

## How configuration works

The only deployment specific value is the API base URL. It is read at runtime from `config.json`:

```json
{ "apiBase": "https://example.invalid/api/v1" }
```

The committed value is a placeholder. The Pages build replaces it with the real backend URL. The app fetches `config.json` with no cache, so changing it takes effect on the next load without a rebuild.

All model calls go through the backend. There is no provider key in the browser and none in this repository.

## Deploy to GitHub Pages

The site is static and every path is relative, so it works under a project subpath such as `https://<user>.github.io/trailpack-app/`.

1. In the repository settings, set Pages to deploy from GitHub Actions.
2. Add a repository variable `API_BASE` with your backend's public address, for example `https://api.example.com/api/v1` (not a secret).
3. Push to `main`. The `pages` workflow runs the tests, runs `node scripts/build-pages.mjs`, and publishes the result.
4. On your backend, allow the site's origin (for example `https://<user>.github.io`) in its CORS setting.

`scripts/build-pages.mjs` copies the site into `_site`, writes `config.json` from `API_BASE`, stamps the build id, and adds a strict Content Security Policy to `index.html` as a meta tag, because Pages cannot send response headers. You can run it locally with `API_BASE=... node scripts/build-pages.mjs`.

## Build id and caching

A single build id names the service worker cache. Stamp one before deploying:

```sh
node scripts/stamp-build.mjs            # git hash plus UTC timestamp
node scripts/stamp-build.mjs --id=1.2.0 # or a value you choose
```

It writes the id into `sw.js`, `src/build-id.js` and `index.html`. Bumping it retires every cached asset at once. The id is shown on the Me screen.

## Tests

```sh
npm test
```

This runs the secret scan (`scripts/secret-scan.mjs`) and then `node --test test/`. The tests are pure logic and loopback HTTP against the mock API. No test reaches the internet.

The secret scan fails on key like strings, `Bearer` tokens, real looking email addresses, private hostnames and private IPs, and on tracked `.env`, key or token files. This repository is public, so it runs on every push.

## Layout

```
index.html              shell, no inline app logic
config.json             API base URL (placeholder)
manifest.webmanifest    PWA manifest
sw.js                   service worker, BUILD_ID names the cache
scripts/build-pages.mjs  builds the GitHub Pages site (config.json, build id, CSP meta tag)
icons/                  logo mark, generated PNG icons
styles/app.css          all styles, dark and light tokens
src/main.js             boot: config, store, i18n, session, router
src/api/client.js       the whole API surface, one request path
src/app/                router, state, i18n wiring, session, prefs, UI helpers
src/i18n/               en, et, es, fr, fi catalogues and the formatter
src/store/              IndexedDB wrapper, file store, low space policy
src/sync/engine.js      outbox, pull, conflict merge, restore
src/screens/            one module per screen
dev/                    mock API (in memory, implements API.md), smoke script
scripts/                secret scan, build stamp, icon generation
test/                   node --test suites
```

`icons/*.png` are generated by `node scripts/make-icons.mjs` from the same shape as `icons/mark.svg`.

## Privacy

Trailpack stores study data on your device first. Sync sends it only to the backend configured for your app. Use your own backend; do not put API keys, passwords or other secrets in this public repository. Model requests go through that backend. There are no analytics or third-party scripts.
