# Build spec: trailpack-app (PUBLIC frontend, a single page web app)

You are building the web frontend for Trailpack, an invite only study app. **This repo will be public on GitHub.** Read `API.md` (the backend contract, follow it exactly), `design/design-and-brand.md` (product, activities, mixer, mastery, gamification, languages) and `design/visuals.html` (the look: copy the CSS variables, spacing, components and screen layouts, dark and light themes). The `design/` folder is git ignored and is for you only.

## Hard rules (public repo)
1. **No secrets, no private data, anywhere.** No API keys, tokens, passwords, emails, real names, employer or interview content, internal hostnames, subscription or tenant ids. The visuals file contains sample names (for example a job interview pack and people's names): **do not copy any of that sample content**. Use neutral demo content only (for example a generic "Intro to project management" pack).
2. The only deployment specific value is the API base URL, read at runtime from `config.json` (`{"apiBase":"https://example.invalid/api/v1"}` committed as a placeholder; the real value is injected at deploy). All model calls go through the backend. The browser never holds a provider key.
3. **Do not read anything outside this folder** (especially `~/.config`). Do not push, create remotes or deploy. Commit locally on `main` in small commits. A human reviews and deploys.
4. Be honest in `STATUS.md`: say what runs, what you tested, what is missing.

## Stack and shape
- **SPA, vanilla ES modules, no build step**, no framework, no CDN. Self host any font or library file you need (keep dependencies near zero). `index.html`, `src/` modules, `styles/`, `config.json`, `sw.js`, `manifest.webmanifest`, icons (SVG logo from the visuals: the switchback mark).
- **Hash router** (`#/trail`, `#/study`, and so on), so no server rewrite rules are needed and it works on any static host, including a GitHub Pages subpath (all asset paths are relative). A strict Content-Security-Policy (`default-src 'self'`; `connect-src 'self'` plus the API origin; no inline scripts) is added to `index.html` as a meta tag by `scripts/build-pages.mjs`.
- **Local first with sync on by default.** Store everything in IndexedDB (docs by collection, files as blobs, outbox queue). Sync engine: push the outbox when online, pull `GET /sync/changes?since=cursor` on start, on focus and every 60 s; conflicts handled with `baseRev` and a per collection merge (progress and attempts merge per fact or id, packs last writer wins). **Restore:** if local storage is empty or was wiped, after login pull `since=0` and rebuild everything, and lazily re-download files from `/sync/files/:id` when needed. **Low space:** use `navigator.storage.estimate()`; when tight, evict cached file blobs (keep docs), show a calm notice, re-fetch on demand. Call `navigator.storage.persist()`. Show sync status (synced, syncing, offline, error) in Me.
- **Auth:** access screen (study code), create account, login. Keep the refresh token in IndexedDB, the access token in memory, auto refresh. Sign out wipes tokens and optionally local data. There is no public sign up.
- **i18n from the first screen:** catalogues `src/i18n/en.json et.json es.json fr.json fi.json` (English, Estonian, Spanish, French, Finnish). All UI text by key, ICU style plurals (write a tiny formatter, correct for these languages), `Intl` for dates and numbers, layouts that tolerate 30% longer text. App language and study language are separate settings. A test must fail if any catalogue is missing a key that `en.json` has. Mark non English strings as drafts in a `_review` list.
- **Themes:** four themes, copy their CSS variables from `design/visuals.html` (`[data-theme=...]` blocks): `dark` (Grape Night), `light` (Sunrise), `ocean` (Deep Ocean, dark), `matcha` (Matcha Pop, light), plus a `system` option that follows the OS light or dark setting (Grape Night or Sunrise). Theme picker with colour previews in Me, stored in settings and synced (`theme` in `/me` accepts `dark light ocean matcha system`). Every component must use the CSS variables only, no hard coded colours, so all four themes work everywhere. Respect `prefers-reduced-motion`. Accessible: focus rings, aria labels, contrast, 44px targets.
- **PWA:** manifest, service worker with a single `BUILD_ID` constant that names the cache and is stamped by `scripts/stamp-build.mjs`; the offline shell works.

## Milestones (do them in order; commit after each; update `STATUS.md`)
**M1 Shell and account.** Router, themes, i18n, config loader, API client, auth screens (access, create account, login), Me screen (language, theme, sync status, AI model choice Muse or DeepSeek Flash from `/llm/models`, delete account, sign out), Admin screen (owner only: create, list and revoke study codes, accounts, usage), sync engine with IndexedDB, service worker, and a dev mock API `dev/mock-api.mjs` implementing the contract with in memory data so you can run and test without the real backend (`node dev/mock-api.mjs`, serve the folder statically).
**M2 Library and ingest.** Add documents (drop, pick, paste text): send each file to `/ingest/extract`, store the source file via `/sync/files`, chunk the text (150 to 400 words with source anchors), call `/llm/chat` with task `ingest_map` to produce topics and atomic facts (JSON), show the review screen (topics, fact counts, merge, rename, drop), then freeze to a Pack. Each fact gets 3 or more variants (generated with task `generate`) stored on the fact. Adding documents later merges new facts without touching existing progress.
**M3 Study engine.** Bites (3 to 5 minutes, 6 to 10 steps) built by the **Session Mixer** exactly as in design section 3.9 (auto rules, manual matrix of activity type by learning state, presets, per camp override, safety fallback to flashcard). **Mastery engine** exactly as in 3.10 (states New, Learning, Review, Mastered, Lapsed, Weak; schedule 10 min, 1, 3, 7, 14, 30 days; mastered = 3 correct recalls, 3 days, 2 formats, one from memory; intake about 30% new and adaptive; when new material is exhausted keep repeating weak, due, learning, then mastery sweeps). Activities to implement: flashcard, multiple choice, true or false, swipe quiz, fill the blank, match pairs, put in order, spot the mistake, blitz, teach it back (LLM, task `teach`), mastery sweep, listen (Web Speech synthesis), voice answer (Web Speech recognition where available, editable transcript, coverage check, optional LLM score). The others in the design (practice task with hint ladder, visual task, scenario, story rehearsal, boss round, mock exam) as lighter versions if time allows. Trail with Camps and gates (70%), Daily Walk, readiness score, deadline mode.
**M4 Gamification, Lens, exports.** Points, levels, answer streak, day streak, plan streak, Shortcuts wallet (rules in design section 4), achievements (full table in the design), variety bonus, bite complete screen with confetti (reduced motion safe), summit certificate as PNG via canvas. **Lens:** a prompt bar; `/llm/chat` task `lens` returns a lens diff (JSON) shown for approval; only generated items that depend on changed lens fields regenerate; facts and progress are untouched. Exports: Markdown study guide, cheat sheet, Anki tab separated file, print stylesheet for PDF (window.print), per camp.

## Tests (`node --test`, pure logic only, no DOM, no network)
Mixer rules (no same type twice in a row, max 2 per bite, at least 3 types, matrix respected, fallback), mastery scheduler and state machine, intake adaptation, exhausted new material loop, i18n key completeness and plural formatter for all five languages, sync outbox and conflict merge, chunker, lens dependency tracking. Plus `scripts/secret-scan.mjs` (fails on key like strings, emails, `Bearer ` literals, private hostnames) run as part of `npm test`.

## Definition of done
All milestones you can finish with tests green; honest `STATUS.md`; `README.md` (what it is, how to run with the mock API, how config works, no private info); `.gitignore` includes `design/`, `node_modules`, `.env`; `.github/workflows/secret-scan.yml` running the scan and tests on push (no secrets in the workflow).
